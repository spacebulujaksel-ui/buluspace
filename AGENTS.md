## Detail fitur cuti — cara kerja & titik rawan (untuk AI debug)
**Alur end-to-end cuti:**
1. Admin: modal "Jadwal Cuti" di `admin/src/pages/Therapists.tsx` → `addLeave()` → `POST /admin/therapists/{id}/leaves` (backend `Admin/TherapistController@storeLeave`) → validasi `start_date`/`end_date` (input `type=date` → format `Y-m-d`) → insert ke tabel `therapist_leaves`.
2. Booking (`Api/BookingController@store`): hitung `$leaveIds` untuk tanggal booking (`TherapistLeave::whereDate(start_date,'<=')...'` → `pluck('therapist_id')`); pilih tertentu & termasuk cuti → `422 "Terapis sedang cuti pada tanggal tersebut..."`; auto-assign → terapis di-filter `false` dari kandidat.
3. Website `BookingModal`: `/availability?date=...&location=...` mengembalikan `on_leave_ids` → terapis cuti di-disable + auto-unselect (`useEffect` reset ke `"any"`) + tooltip "sedang cuti pada tanggal ini".

**PENTING (berubah 2026-09-28):** `status` terapis TIDAK lagi diubah oleh cuti. Command `SyncTherapistLeaveStatus` (dan blok auto-inactive di `storeLeave`, dan `Therapist::isOnLeaveOn`) **SUDAH DIHAPUS** karena menjalankan `Active→Inactive` satu-arah tanpa pernah membalik → satu hari cuti mengunci terapis selamanya (Ira id 15 & Silva id 12 kena di 28 Sep). Sekarang blokir cuti 100% dari `$leaveIds`/`on_leave_ids` yang berdate; `status` murni saklar manual staf. Terapis yang tadinya terkunci dipulihkan via migration `2026_09_28_000001_reactivate_auto_inactive_therapists` (Inactive + sedang cuti hari itu → Active).

**Titik rawan / urutan cek saat error:**
- **Timezone server = UTC** (`config/app.php` 'timezone' => 'UTC') — tanggal di `$leaveIds`/`$offDayIds` dihitung dari `appointment_date` (input frontend, WIB), jadi aman; jangan pakai `today()`/`now()` UTC untuk memutuskan tanggal booking.
- **Format tanggal** harus konsisten `Y-m-d`; jangan biarkan string `datetime` masuk ke `whereDate` (`slice(0,10)` dipakai di frontend untuk memotong).
- **Branch-scoped:** `TherapistController@scoped($id)` memakai `branch_id` admin → terapis/branch lain tidak terlihat. Data "hilang" biasanya karena ini.
- Bug dikenal tersisa: `storeLeave` belum menolak rentang cuti bertumpuk.
- Tombol **Selesai**: `PUT /admin/bookings/{id}/status` body `{status:"Completed"}` (route admin). Jika 422, cek status saat ini (cuma dari `Confirmed` normalnya).

## Detail fitur hari libur rutin (off day) — 2026-09-28
Pola libur **tetap tiap minggu**, BEDA dari cuti (rentang tanggal). Status terapis tidak pernah diubah. Blokir dari `day_of_week_iso` (1=Senin..7=Minggu).
- Tabel `therapist_off_days` (`therapist_id` + `day_of_week_iso`, unique) — migration `2026_09_28_000003` juga seed roster.
- Roster: **Jaksel** Senin=Ira, Selasa=Siti/Anisha/Ros, Rabu=Dwi/Kayla/Lya, Kamis=Putri/Nazua; **Jakbar** Senin=Silva, Selasa=Silvia, Rabu=Amanda, Kamis=Diah. Jumat–Minggu kosong.
- Enforcement (`Api/BookingController@store`): hitung `$offDayIds` dari `Carbon::parse($appointment_date)->dayOfWeekIso`; pilih eksplisit di hari libur → `422 "Terapis sedang libur pada hari tersebut (hari libur rutin). Silakan pilih terapis lain."`; auto-assign melompati.
- Website: `availability` mengembalikan `off_day_ids` per weekday tanggal → `BookingModal` kartu terapis abu-abu + tooltip "sedang libur pada hari ini" + auto-unselect.
- Admin kelola: `Therapists.tsx` modal edit → bagian "Jadwal Libur Rutin" (select Senin..Minggu + hapus), kolom "Libur" di tabel & kartu HP. Routes `POST/DELETE /admin/therapists/{id}/off-days` (backend `Admin/TherapistController@storeOffDay`/`destroyOffDay`, validasi `between:1,7`).
- Test: `tests/Feature/TherapistOffDayTest.php` 4 kasus.
