## Arsitektur inti
- Booking: website → `https://antiquewhite-oyster-416288.hostingersite.com/api` (Laravel, live) → tersimpan di tabel `appointments`.

- `app/Http/Controllers/Api/` — untuk customer: `PublicController` (services/therapists/availability/scheduleBoard/branches/reviews), `BookingController` (store/show/cancel), `PromoController`, `AuthController` (login/me/logout).
- `app/Http/Controllers/Admin/` — dashboard, booking (+ubah status), schedule (+block slot), therapists (+`storeLeave`/`destroyLeave`), services, promos, reviews, email-settings, walk-ins.
- `app/Models/` — `Therapist` (relasi `leaves()`, `isOnLeaveOn($date)`), `TherapistLeave`, `Appointment`(+`AppointmentDetail`), `Service`, `Branch`, `BlockedSlot`, `Schedule`, `Review`, `Promo`, `EmailSetting`, `WalkIn`, `User`.
- `app/Console/Commands/` — `SyncTherapists`/`SyncServices` (seed roaster), `SendH1Reminders`/`SendHourReminders` (email), `SyncTherapistLeaveStatus` (auto-Inactive saat cuti), `TestEmail`, `DedupeDuplicateRecords`, `ImportCalendarCsv` (import booking dari ekspor Google Calendar 3 format CSV — lihat log 2026-09-25), `CleanupTestData` (hapus booking test Jakarta Selatan only).
- `app/Services/BookingMailer.php` — email booking (confirm/H-1/2 jam/aftercare).
- `app/Http/Middleware/EnsureAdmin.php` — guard role admin; `database/migrations/` — skema (termasuk `therapist_leaves`); `tests/Feature/TherapistLeaveTest.php` — test cuti.

**`admin/` (React + Vite + Tailwind, port 5173)**

- `src/components/` — UI dasar (Modal, Button, Badge, DataTable, Sidebar, Header, StatCard).

**`website/` (customer, port 3000)**
- Alur booking inti di `src/components/BookingModal.tsx` (pilih slot, request terapis, `on_leave_ids`), `BookingConfirmationModal.tsx`, `TrackBookingModal.tsx`.

**`jadwal/`** — board jadwal publik (port 5175): `src/App.tsx` + `src/api.ts`.

## Detail fitur cuti — cara kerja & titik rawan (untuk AI debug)
**Alur end-to-end cuti:**
1. Admin: modal "Jadwal Cuti" di `admin/src/pages/Therapists.tsx` → `addLeave()` → `POST /admin/therapists/{id}/leaves` (backend `Admin/TherapistController@storeLeave`) → validasi `start_date`/`end_date` (input `type=date` → format `Y-m-d`) → insert ke tabel `therapist_leaves`.
2. `storeLeave`: jika rentang mencakup hari ini & terapis `Active` → langsung diubah `Inactive`.
3. Booking (`Api/BookingController@store`): hitung `$leaveIds` untuk tanggal booking (`TherapistLeave::whereDate(start_date,'<=')...'` → `pluck('therapist_id')`); pilih tertentu & termasuk cuti → `422 "Terapis sedang cuti pada tanggal tersebut..."`; auto-assign → terapis di-filter `false` dari kandidat.
4. Website `BookingModal`: `/availability?date=...&location=...` mengembalikan `on_leave_ids` → terapis cuti di-disable + auto-unselect (`useEffect` reset ke `"any"`) + tooltip "sedang cuti pada tanggal ini".
5. Scheduler `SyncTherapistLeaveStatus` (tiap jam) → `Active→Inactive` saat sedang cuti (HANYA satu arah — tidak pernah balik).

**Titik rawan / urutan cek saat error:**
- **Timezone server = UTC** (`config/app.php` 'timezone' => 'UTC') — `today()` bisa selisih 7 jam dari WIB. Jika status cuti "telat/lebih cepat" perubahannya, inilah biangnya.
- **Format tanggal** harus konsisten `Y-m-d`; jangan biarkan string `datetime` masuk ke `whereDate` (`slice(0,10)` dipakai di frontend untuk memotong).
- **Branch-scoped:** `TherapistController@scoped($id)` memakai `branch_id` admin → terapis/branch lain tidak terlihat. Data "hilang" biasanya karena ini.
- Bug dikenal: (1) terapis tidak balik `Active` setelah cuti selesai — solusi terpilih opsi a: migration kolom `auto_inactive` + `Therapist::refreshLeaveStatusOn($date)` dua-arah, dipanggil dari `storeLeave`/`destroyLeave`/`SyncTherapistLeaveStatus`; (2) `storeLeave` belum menolak rentang bertumpuk.
- Tombol **Selesai**: `PUT /admin/bookings/{id}/status` body `{status:"Completed"}` (route admin). Jika 422, cek status saat ini (cuma dari `Confirmed` normalnya).
